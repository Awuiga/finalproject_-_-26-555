## Уточнение спорных моментов ТЗ

- В описании `buy` одновременно встречаются «просто зачислить валюту» и «списать USD». Выбрана **полноценная виртуальная покупка за USD**; отдельная команда `deposit-demo` выдаёт тестовые USD для сценария.
- Пример `sell --currency USD` в ТЗ показывает продажу BTC: это опечатка примера. Реализована продажа валюты, указанной аргументом `--currency`; USD→USD отклоняется как бессмысленная операция.
- API фиата возвращает `USD→EUR`, а хранилище ожидает `EUR→USD`; в `ExchangeRateApiClient` выполняется обратное преобразование.
- Для кэша взят формат `{ "pairs": {...}, "last_refresh": ... }` из раздела 4; старые примеры без `pairs` из раздела 2 не используются.

## Команды для проверки и завершения сдачи

В терминале (из папки с `pyproject.toml`, при наличии интернета):

```bash
uv lock
uv sync --group dev
uv run ruff check .
uv run ruff format --check .
uv run pytest -q
uv build
```

Если Ruff сообщает о форматировании, запустить `uv run ruff format .`, затем повторно все проверки.

Для живой проверки Parser Service установить ключ в переменную окружения `EXCHANGERATE_API_KEY`, запустить `uv run valutatrade`, затем `update-rates` и `show-rates`. Если CoinGecko ограничивает доступ или источник недоступен, это должно сопровождаться сообщением об ошибке; не выдавайте DEMO-значения за реальные курсы.

**Точный оставшийся риск:** отсутствие зафиксированного `uv.lock`, непроверенный Ruff, непроверенная сборка и недоступные в этой среде живые API. Пока эти пункты не закрыты, **абсолютное соответствие всем требованиям не доказано**.
